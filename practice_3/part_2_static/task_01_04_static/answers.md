# Задания 1–4: статические поля и методы

## 1. Допустимость обращений

При условии, что `f` ссылается на созданный объект `F`, допустимы пункты **1, 2, 3, 4, 6, 8**. Пункты 5 и 7 недопустимы: `i` и `imethod()` принадлежат экземпляру, поэтому через имя класса без объекта к ним обратиться нельзя. Пункты 2 и 4 компилируются, но статические члены принято вызывать через имя класса: `F.s` и `F.smethod()`.

## 2. Где нужно static

`main` должен быть статическим. `getCount()` обращается к полю экземпляра `count`, поэтому остаётся нестатическим. `factorial` не использует состояние объекта, поэтому его можно сделать статическим; это не обязательно для корректности самого метода.

## 3. Статический и нестатический контекст

1. Из статического метода можно обращаться к полям и методам экземпляра только через ссылку на конкретный объект, например `object.method()` или `object.field`.
2. Из метода экземпляра можно вызывать статические методы и читать статические поля, предпочтительно через имя класса.
3. В исходной программе `main` вызывает нестатический `method1()` без объекта, а статический `method2()` обращается к нестатическому полю `c`. Один вариант исправления — создать объект `C` в `main` и сделать `method2()` методом экземпляра. Он показан в `Main.java`.

## 4. Массив Date

`new Date[10]` создаёт массив из десяти ссылок `null`, а не десять объектов дат. Вывод `dates[0]` напечатает `null`, но `dates[0].toString()` вызовет `NullPointerException`. Перед обращением нужно создать объект, например `dates[0] = new Date()`.
